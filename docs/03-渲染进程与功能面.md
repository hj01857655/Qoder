## 4. 语音 / 会议子系统（意外发现）

### 4.1 常量族

渲染进程存在完整的 `VOICE_*` 常量组：

```
VOICE_CONTEXT                    VOICE_CONTEXT_MAX_LENGTH
VOICE_DISCUSSION_STORAGE_KEY     VOICE_AUDIO_DEVICE_PREFERENCE_CHANGED_EVENT
VOICE_IDS                VOICE_ID_MIGRATIONS
VOICE_HISTORY_RESTORE_FAILED      VOICE_HISTORY_RESTORE_ERROR_CODE
```

配套存储键：

```
DJI_MIC_AUTO_SEND_STORAGE_KEY     ← 麦克风按键自动发送
voice_discussion_summary          ← 语音讨论摘要
voice_first_use                   ← 首次使用引导
```

`VOICE_ID_ID_MIGRATIONS`（`VOICE_ID_MIGRATIONS`）说明**语音会话 ID 有版本迁移逻辑**，即该功能经历过迭代。

### 4.2 原生配合

与 `resources/bin/dji_mic_button.node`（767 KB）呼应——**"DJI" 指大疆设备的麦克风按键**，用于「按下说话」式语音输入。

推测工作流：

```
麦克风按键（原生 node 捕获）
  → VOICE_AUDIO_DEVICE_PREFERENCE（设备选择）
  → 录音 / 语音识别
  → voice_discussion_summary（生成讨论摘要）
  → 注入 Agent 上下文（VOICE_CONTEXT）
  → DJI_MIC_AUTO_SEND（自动发送配置）
```

### 4.3 会议侧

`callable` / `CallCount` / `callers` / `CallExplanation` 等高频标识，以及 API 层的 `collaboration/runtime`（28 条路径）与 `collaboration/discussions`（26 条）——

**Qoder 的 "discussion" 很可能是语音+Agent 混合的协作单元**，不只是文本会话。

## 8. 小结

Qoder CN 渲染进程**不是常规 IDE 前端**，而是集成了：

- Agent 编排（最高权重）
- 语音/会议协作
- 演示文稿、图表、排版、Office 文档
- 浏览器自动化
- 图谱可视化（含 Cynefin 认知框架）

定位更接近 **"AI 工作台"** 而非 IDE——与 `package.json` 里 `@qoder-space/workbench` 的命名一致。
