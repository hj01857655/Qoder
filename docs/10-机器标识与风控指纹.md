# 10 · 机器标识与风控指纹（runtime-info.exe）

取证日期：2026-10-09。方法：app.asar 代码逆向 + `runtime-info.exe` 实调 + app 日志分析。

## 1. 概述

Qoder CN 通过 `runtime-info.exe` 生成硬件指纹，注入 `Cosy-Machine*` 系列请求头。服务端用这些头做风控——奶茶免单卡等活动只在携带完整机器标识时才返回，claim 缺这些头时返回 503 `SAME_PERSON_DEPENDENCY_UNAVAILABLE`。

## 2. 机器标识组成

| 头 | 来源 | 示例值 |
|---|---|---|
| `Cosy-MachineId` | `auth.machine-id` 文件（纯文本 UUID） | `e2eae331-5ffa-4fcc-952a-a4475f5b237d` |
| `Cosy-MachineToken` | `runtime-info.exe` stdout | `P1gApKzl1y5VBP9ByYhuOaRBsU_...`（80 字符） |
| `Cosy-MachineCode` | `runtime-info.exe` stdout | `4c06552d765a82916e`（18 字符） |
| `Cosy-MachineType` | `runtime-info.exe` stdout | `4987ea7614ca63c7d0`（18 字符） |
| `Cosy-MachineOS` | `process.platform` | `win32` |
| `Cosy-MachineHostname` | `os.hostname()` | 主机名 |

## 3. runtime-info.exe

### 位置

```
%LOCALAPPDATA%\Programs\Qoder CN\resources\umid\runtime-info.exe
```

### 调用协议

```
runtime-info.exe <environment> --account-stdin
```

- **environment**：`0` = 非 global，`3` = global
- **--account-stdin**：从 stdin 读取 account JSON
- **stdin**：`JSON.stringify({account: <account_info>})` 右侧 pad 空格至 80 字节
- **stdout**：机器标识 JSON
- **返回码**：0 = 成功

### 实调示例

```bash
echo '{"account": null}                        ' | runtime-info.exe 0 --account-stdin
```

### 输出

```json
{
  "machineToken": "P1gApKzl1y5VBP9ByYhuOaRBsU_pOe9Cp6jyz3d45v5zEtVTD8sWWwMsMUFB2Pd94KPdXbGeOxhdb-tvwNQJGxSn",
  "machineType": "4987ea7614ca63c7d0",
  "machineCode": "4c06552d765a82916e",
  "vmInfo": {
    "isVm": true,
    "brand": "Hyper-V",
    "percentage": 77,
    "vmTypeCode": 14
  },
  "accountOutcome": "invalid_input"
}
```

**注意**：`accountOutcome: "invalid_input"` 表示 account 参数无效，但 `machineToken`/`Type`/`Code` 仍正常返回——这三个值基于硬件指纹，不依赖 account。`vmInfo` 检测虚拟机环境（Hyper-V 77% 置信度）。

## 7. auth.v1.dat 解密（Electron safeStorage）

### 格式

```
auth.v1.dat = "v10" (3B) + nonce (12B) + AES-256-GCM ciphertext + tag (16B)
```

AES-256-GCM 密钥**不在 auth.v1.dat 里**，而是存储在 `Local State` 文件中。

### 密钥提取

`Local State`（JSON）→ `os_crypt.encrypted_key`（Base64）→ 解码后前 5 字节为 `DPAPI` → 剩余部分为 DPAPI 加密的 AES-256 密钥。

```
Local State → os_crypt.encrypted_key → Base64 decode → strip "DPAPI" (5B) → DPAPI decrypt → AES-256 key (32B)
```

Windows DPAPI 解密用 `System.Security.Cryptography.ProtectedData.Unprotect(blob, null, CurrentUser)`，scope 为当前用户（不需要密码）。

### 解密流程

```python
# 1. 从 Local State 提取 AES 密钥
local_state = json.load(open("Local State"))
enc_key = base64.b64decode(local_state["os_crypt"]["encrypted_key"])
assert enc_key[:5] == b"DPAPI"
aes_key = dpapi_decrypt(enc_key[5:])  # → 32 字节 AES-256 密钥

# 2. AES-256-GCM 解密 auth.v1.dat
raw = open("auth.v1.dat", "rb").read()
assert raw[:3] == b"v10"
nonce, tag = raw[3:15], raw[-16:]
ciphertext = raw[15:-16]
plaintext = AES_GCM_decrypt(aes_key, nonce, ciphertext, tag)
```

### 跨平台

| 平台 | 密钥来源 | 加密算法 |
|---|---|---|
| Windows | `Local State` → DPAPI | AES-256-GCM，nonce 12B + tag 16B |
| macOS | Keychain `<AppName> Safe Storage` → PBKDF2(password, 'saltysalt', 1003, 16) | AES-128-CBC，IV = 16 × 0x20 |
| Linux | 硬编码 `'peanuts'` → PBKDF2('peanuts', 'saltysalt', 1, 16) | AES-128-CBC，IV = 16 × 0x20 |

macOS v11 需系统密钥环，暂不支持。参考实现：[techysy/CreditDaddy](https://github.com/techysy/CreditDaddy) `src/qoderApp.js`。

## 8. 网关中的使用

`benefit.py` 的 `_get_machine_identity()` 调用 `runtime-info.exe` 获取机器标识，`_get_machine_id()` 读 `auth.machine-id` 文件，`_headers()` 合并后注入所有 campaigns API 请求。机器标识在进程内缓存，避免重复调用 `runtime-info.exe`。
